# 메이플스토리 월드(MSW) 설정 UI — 기능 구현 요청 프롬프트

## A. 기능 점검 결과 (구현이 필요한 항목)

화면에 보이는 요소들을 "겉모습은 있지만 동작이 없는 상태"로 보고, 실제로 코드가 필요한 지점을 정리했다.

### A-1. 사운드 설정

| # | 필요한 기능 | 점검 포인트 |
|---|---|---|
| 1 | 슬라이더 값 상태 관리 | 0~100 정수 스냅, 드래그 중 퍼센트 텍스트 실시간 갱신 |
| 2 | 3채널 볼륨 분리 | 배경 음악 / 효과음 / 음성이 각각 독립 채널로 동작해야 함 |
| 3 | 실제 사운드 반영 | BGM은 즉시, 효과음·음성은 재생 시점에 볼륨이 적용되도록 재생 경로를 일원화 |
| 4 | 0~100 → 0.0~1.0 매핑 | 0%일 때 완전 음소거, 재생 자체를 건너뛸지 볼륨 0으로 재생할지 결정 필요 |
| 5 | 조절 피드백 | 효과음·음성 슬라이더를 놓는 순간 샘플 사운드 1회 재생(미리듣기) |

### A-2. 키 전환

| # | 필요한 기능 | 점검 포인트 |
|---|---|---|
| 6 | 입력 대기(캡처) 모드 | 키 버튼 클릭 → 다음 키 입력을 가로채 할당, 한 번에 하나만 대기 상태 |
| 7 | 중복 키 검사 | 이미 다른 액션이 쓰는 키는 거부하고 안내 문구 표시 |
| 8 | 예약/금지 키 처리 | ESC(취소), 시스템·UI 단축키는 할당 불가 처리 |
| 9 | **입력 시스템 연동(가장 중요)** | 캐릭터 조작 코드가 하드코딩된 키를 보지 않고 **바인딩 테이블을 조회**하도록 바꿔야 실제로 키 변경이 먹힘 |
| 10 | 설정 창 열림 중 입력 차단 | 창이 열려 있는 동안 캐릭터 이동·점프·공격 입력이 들어가지 않아야 함 |
| 11 | 리스트 스크롤 | 항목이 5개를 넘을 때 스크롤 동작 |

### A-3. 저장 / 불러오기

| # | 필요한 기능 | 점검 포인트 |
|---|---|---|
| 12 | PlayerData 스키마 | 볼륨 3개 + 키 매핑 테이블 + 버전 필드 |
| 13 | 저장 시점 | "적용"을 눌렀을 때만 영속화 |
| 14 | 로드 시점 | 플레이어 입장 시 로드해 게임 전체에 반영, 창을 열 때 UI에 반영 |
| 15 | 유효성 검사 / 마이그레이션 | 저장값이 없거나 손상됐을 때 기본값 폴백, 액션 항목이 추가돼도 안전하게 병합 |

### A-4. 창 전체 흐름

| # | 필요한 기능 | 점검 포인트 |
|---|---|---|
| 16 | 임시 상태(pending) 관리 | 화면에서 만진 값은 임시 상태에 두고 "적용" 전까지 확정하지 않음 |
| 17 | 사운드 실시간 프리뷰 + 롤백 | 볼륨은 조절 즉시 들려야 하되, 저장 없이 닫으면 마지막 저장값으로 되돌림 |
| 18 | 변경 감지(dirty check) | 변경사항이 있는 상태로 X를 누르면 확인 처리 |
| 19 | 기본값 복원 범위 | 사운드+키 전체를 되돌릴지, 현재 탭만 되돌릴지 결정 필요 |
| 20 | 탭 전환 | 좌측 탭 클릭 시 해당 섹션 노출 + 하이라이트 갱신 |
| 21 | 창 열기/닫기 진입점 | ESC 또는 HUD 버튼으로 토글, 중복 오픈 방지 |
| 22 | 클라이언트 전용 처리 | 설정은 로컬 값이므로 클라이언트에서 처리하고 서버로 동기화하지 않음 |
| 23 | 모바일 대응 | 물리 키보드가 없는 환경에서 "키 전환" 탭을 숨기거나 비활성화 |

## B. 구현 요청 프롬프트 (그대로 복사해서 사용)

메이플스토리 월드(MapleStory Worlds)에서 이미 만들어 둔 **설정(Settings) 팝업 UI에 실제 동작을 붙여줘.**
레이아웃과 디자인은 완성돼 있고, 지금 필요한 건 기능 로직이야. Lua 스크립트로 구현해줘.

작업 시작 전에 프로젝트에 이미 있는 사운드 재생 코드, 캐릭터 입력 처리 코드, `PlayerData` 저장 컴포넌트를 먼저 확인하고,
어떤 파일을 수정할지 알려준 다음 진행해줘. MSW API 이름은 추측하지 말고 실제 지원되는 것으로 확인해서 써줘.

### 1. 설정 상태 모델

- 설정값을 한 곳에서 관리하는 모듈(`SettingsManager` 같은 이름)을 만들어줘. 아래 두 벌의 상태를 구분해서 관리해줘.
  - **저장 상태(saved)**: `PlayerData`에 마지막으로 저장된 값.
  - **임시 상태(pending)**: 창에서 사용자가 만지는 중인 값. "적용"을 눌러야 저장 상태로 확정돼.
- 데이터 구조는 이렇게 해줘.
  ```lua
  {
    version = 1,
    volume  = { bgm = 70, sfx = 80, voice = 60 },   -- 0~100 정수
    keys    = { MoveLeft = "A", MoveRight = "D", Jump = "Space", Attack = "J", Dash = "K" }
  }
  ```
- 값이 바뀌면 구독자에게 알리는 이벤트/콜백을 제공해줘(사운드 시스템과 입력 시스템이 여기에 붙게).

### 2. 사운드 기능

- 배경 음악 / 효과음 / 음성을 **독립된 3채널**로 관리하고, 각 채널의 볼륨을 설정값에서 가져오게 해줘.
- 슬라이더 값은 0~100 정수 단위로 스냅되고, 드래그하는 동안 우측 퍼센트 텍스트가 실시간으로 갱신돼야 해.
- 내부적으로는 0~100을 0.0~1.0으로 변환해서 실제 재생 볼륨에 반영해줘. **0%는 완전 무음**이어야 해.
- 배경 음악은 슬라이더를 움직이는 즉시 볼륨이 바뀌어야 하고, 효과음·음성은 **슬라이더를 놓는 순간 샘플 사운드를 1회 재생**해서 크기를 확인할 수 있게 해줘.
- 게임 안의 모든 사운드 재생이 이 채널 볼륨을 거치도록, 재생 호출 지점을 공통 함수로 정리해줘.

### 3. 키 전환 기능

- 키 버튼을 클릭하면 **입력 대기 상태**로 진입해줘. 버튼 텍스트를 `...`로 바꾸고 강조 테두리를 주고, 한 번에 하나의 버튼만 대기 상태일 수 있어.
- 대기 상태에서 다음에 누른 키를 해당 액션에 할당하고 대기를 해제해줘.
- **중복 검사**: 이미 다른 액션에 할당된 키를 누르면 할당하지 말고 "이미 사용 중인 키입니다" 안내를 잠깐 표시한 뒤 원래 키를 유지해줘.
- **예약 키**: ESC는 대기 취소 전용이라 할당 불가, 그 외 UI/시스템 단축키도 금지 목록으로 빼서 거부해줘.
- **입력 시스템 연동이 핵심이야.** 캐릭터 이동·점프·공격·대시 코드가 특정 키를 직접 비교하고 있다면, 액션 이름으로 조회하는 방식(`Settings.IsActionPressed("Jump")` 같은 형태)으로 바꿔줘. 설정에서 키를 바꾸면 실제 조작에 바로 반영돼야 해.
- 설정 창이 열려 있는 동안에는 캐릭터 조작 입력이 들어가지 않게 막아줘. 창을 닫으면 정상 복구돼야 해.
- 키 항목이 5개를 넘어가면 리스트가 세로로 스크롤되게 해줘.

### 4. 저장 / 불러오기

- **적용** 버튼: 임시 상태를 저장 상태로 확정하고 `PlayerData`에 저장한 뒤 창을 닫아줘. 저장 성공 여부를 확인하고 실패 시 안내해줘.
- **불러오기**: 플레이어가 입장할 때 저장값을 읽어 사운드·입력 시스템에 반영하고, 창을 열 때 UI에 채워줘.
- 저장값이 없거나 형식이 깨졌으면 기본값(70/80/60, A·D·Space·J·K)으로 폴백해줘.
- `version` 필드를 두고, 나중에 액션 항목이 추가돼도 저장된 값과 기본값을 **병합**해서 누락된 항목만 기본값으로 채우게 해줘.
- 설정은 플레이어 개인 값이니까 클라이언트에서 처리하고 서버로 동기화하지 말아줘. (저장만 서버 저장소를 쓴다면 그 경로는 유지)

### 5. 창 전체 동작

- **기본값 복원**: 사운드와 키 전체를 기본값으로 되돌리되, 임시 상태만 바꾸고 저장은 "적용"을 눌러야 확정되게 해줘. 되돌린 직후에도 사운드 프리뷰는 즉시 반영돼야 해.
- **닫기(X)**: 저장하지 않고 닫아줘. 이때 프리뷰로 바꿔 둔 볼륨과 대기 중이던 키 상태는 **마지막 저장값으로 롤백**해줘. 변경사항이 있으면 "저장하지 않고 닫을까요?" 확인을 한 번 띄워줘.
- **탭 전환**: 좌측 "사운드 설정 / 키 전환" 탭을 누르면 해당 섹션으로 이동하고 선택 하이라이트가 갱신돼야 해.
- **열기/닫기 진입점**: ESC 키 또는 HUD 버튼으로 토글하고, 이미 열려 있으면 중복으로 열리지 않게 해줘.
- **모바일**: 물리 키보드가 없는 환경에서는 "키 전환" 탭을 숨기거나 비활성화하고, 슬라이더는 터치 드래그로 조작 가능해야 해.

### 6. 산출물 요구사항

- 스크립트를 역할별로 나눠줘: 설정 상태·저장(`SettingsManager`), UI 바인딩(팝업 컴포넌트), 입력 액션 조회(`InputBinding`), 사운드 채널(`SoundManager`).
- 각 함수에 주석을 달고, 어떤 컴포넌트/엔티티에 붙이는 스크립트인지 명시해줘.
- 아래 항목은 직접 확인해서 결과를 알려줘.
  1. 볼륨을 바꾸고 저장 → 게임 재접속 후에도 유지되는지
  2. 점프 키를 Space에서 다른 키로 바꾼 뒤 실제로 그 키로 점프되는지
  3. 이미 사용 중인 키를 할당하려 할 때 거부되는지
  4. 값을 바꾸고 저장 없이 닫았을 때 이전 값으로 돌아오는지
- MSW에서 지원하지 않아 대체 구현이 필요한 부분이 있으면 임의로 진행하지 말고 먼저 알려줘.

## C. 짧은 버전

메이플스토리 월드에서 이미 만들어 둔 설정 팝업 UI에 **동작 로직**을 붙여줘. 디자인은 완성돼 있고 기능만 없어.

1. **설정 상태 모듈**: `{ volume = {bgm, sfx, voice}, keys = {MoveLeft, MoveRight, Jump, Attack, Dash} }` 구조로 관리하고, "적용" 전까지는 임시 상태로만 들고 있어줘.
2. **사운드**: 배경 음악·효과음·음성을 독립 채널로 나눠 슬라이더 값(0~100)을 실제 볼륨(0.0~1.0)에 반영해줘. BGM은 즉시 반영, 효과음·음성은 슬라이더를 놓을 때 샘플 사운드 1회 재생, 0%는 완전 무음.
3. **키 전환**: 키 버튼 클릭 → 입력 대기(`...`) → 다음에 누른 키로 할당. 중복 키는 "이미 사용 중인 키입니다"로 거부, ESC는 취소. **캐릭터 조작 코드가 하드코딩된 키 대신 액션 이름으로 바인딩을 조회하도록 바꿔서 변경이 실제로 먹히게 해줘.** 설정 창이 열려 있는 동안은 캐릭터 입력을 막아줘.
4. **저장/불러오기**: "적용"을 누를 때만 `PlayerData`에 저장하고 창을 닫아줘. 플레이어 입장 시 불러와 게임에 반영하고, 저장값이 없거나 깨졌으면 기본값(70/80/60, A·D·Space·J·K)으로 폴백해줘.
5. **버튼 동작**: "기본값 복원"은 임시 상태만 기본값으로 되돌리고, "닫기(X)"는 저장 없이 닫으면서 볼륨·키를 마지막 저장값으로 롤백해줘.

작업 전에 기존 사운드·입력·`PlayerData` 코드를 확인하고 수정 대상 파일을 먼저 알려줘. 구현 후에는 재접속 시 값 유지, 변경한 키로 실제 조작, 중복 키 거부, 저장 없이 닫았을 때 롤백 네 가지를 직접 확인해서 결과를 알려줘.
